## Report writing
As you should be about to hand in your first report today we're going to have 
some practice at evaluating some previous reports. In this exercise directory
you should be able to find 'dummy_assignment.pdf'. This is not an assignment
you need to complete yourself as it is the old A0. What you should do is read
through it so you are familiar with its tasks. Alongside the assignment has 
been included three sample reports. Note that the included reports are 
editted version of previous students work. I've cut out any 
identifying information and just used the first latex template that I had 
available, these shouldn't therefore be taken as explicit guidance on how to 
format a report. For instance, you should make sure to include things like your 
names, a title etc. etc. 

Note that I have not included any code submission, which should be a part of your own assignment submission. This is for two reasons, firstly this exercise isn't about reviewing code, but secondly because you shouldn't need to depend on your reader looking at your code to understand what you've done. The report should be its own standalone piece that adequately explains what problem you've solved, how it went, and if your solution worked. 

Your task is to read each of the three sample assignments and evaluate them. 
You can complete this task on your own or with others, but it would perhaps
be most helpful if you completed it with your own assignment group so that you
can all work out what works and what doesn't in the same assignments together.

When evaluating them you should consider the requirements for the API set out
in section 2, and the specific tasks set out in section 5. You can also consider the following general questions. 

* Is the report well written? It doesn't have to be pretty literature, but it does need to make sense
* Is the report well structured? Does it clearly introduce the problem and conclude it all nicely. 
* Is the code well explained? Do you still have major questions about what code was actually written or if it works?
* Is testing explained? Is there an explanation of what has been tested and what the limits of the system are?
* Have you been left in any doubt as to the writers understanding? Did they seemingly avoid discussing any tricky topics you'd expect to crop up in this assignment, or handwave complex definitions?
* Is the report too long or too short? We don't have any strict page requirements but most reports in CompSys will probably end up around 5-10 pages or so. Much shorter than that is often (but not always) a sign that not enough information has been included, and too long is often a sign of just waffling that could be cut.
